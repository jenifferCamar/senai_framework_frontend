# Aula 06 — Gestão de projetos front-end

[← Voltar ao índice](../../README.md) · [Abrir material da aula](material-aula-06.pdf)

## Objetivos

- Organizar pessoas, tarefas, tecnologias e prazos de um projeto front-end.
- Transformar uma ideia em requisitos claros e itens de backlog.
- Priorizar, estimar e acompanhar atividades.
- Definir critérios objetivos para considerar uma tarefa concluída.
- Aplicar práticas de Scrum, Kanban, branches e Sprints ao Projeto Integrador.

## Resumo

Projetos front-end podem crescer rapidamente. Sem planejamento, surgem tarefas esquecidas, requisitos confusos, retrabalho, conflitos no Git, atrasos e problemas de integração. A gestão organiza o trabalho e cria responsabilidades claras, prioridades definidas, entregas incrementais e acompanhamento do progresso.

O fluxo recomendado parte de uma ideia, transforma-a em requisitos, organiza os itens no backlog, prioriza e estima as atividades, desenvolve, revisa, testa e disponibiliza as entregas.

## Requisitos, histórias e tarefas

- **Requisito:** necessidade que o sistema deve atender, como permitir o gerenciamento de tarefas.
- **História de usuário:** descreve uma necessidade sob a perspectiva de quem usa o sistema. Exemplo: “Como usuário, quero criar uma tarefa”.
- **Tarefas:** partes executáveis da história, como criar o formulário, criar o componente, validar campos, integrar a API e criar testes.

## Backlog, prioridade e estimativa

O backlog reúne funcionalidades, melhorias, correções e outras atividades necessárias para desenvolver e evoluir o produto. Cada item deve receber uma prioridade para orientar o que será feito primeiro.

As estimativas representam a complexidade relativa das atividades. Elas ajudam a equipe a selecionar um conjunto viável de tarefas para uma Sprint e a acompanhar o esforço necessário sem confundir estimativa com prazo exato.

## Definition of Done

A **Definition of Done** reúne os critérios que uma tarefa precisa cumprir para ser considerada concluída. Um item pode exigir:

- código implementado;
- testes realizados;
- revisão concluída;
- responsividade verificada;
- integração realizada;
- documentação atualizada;
- branch integrada sem conflitos.

## Scrum, Sprint e Kanban

Scrum é um framework ágil para desenvolver produtos complexos de forma incremental, com inspeção frequente, adaptação e entregas contínuas. A equipe pode organizar o trabalho em Sprints, acompanhar o fluxo em um quadro Kanban e revisar o progresso ao final de cada ciclo.

Branches devem separar funcionalidades e correções do código principal. Commits pequenos e claros ajudam a registrar a evolução e facilitam a colaboração.

## Atividade

Planejar a gestão do Projeto Integrador Interdisciplinar utilizando:

1. backlog;
2. prioridades;
3. tarefas;
4. estimativas;
5. Sprint;
6. quadro Kanban;
7. branches;
8. critérios de conclusão.

O processo deve ser documentado em um arquivo Markdown, e o board criado deve ser utilizado para acompanhar a gestão do projeto.

## Checklist

- [ ] Os requisitos estão claros e divididos em histórias e tarefas.
- [ ] O backlog está organizado por prioridade.
- [ ] As tarefas possuem estimativas.
- [ ] A equipe definiu uma Sprint e um quadro Kanban.
- [ ] As branches e o fluxo de integração estão definidos.
- [ ] A Definition of Done foi registrada.
- [ ] O processo está documentado em Markdown.
